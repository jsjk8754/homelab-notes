## 1. 문제

홈랩과 보안 공부는 설치가 끝난 순간보다 판단과 검증 과정에 더 많은 정보가 남습니다. 하지만 메모가 명령어 조각, 작업 후기, 저장소로 흩어지면 다시 찾기 어렵고 다른 사람도 작업의 맥락을 이해하기 어렵습니다.

이 프로젝트는 한 번의 학습에서 세 가지 결과물을 만드는 구조를 정의합니다.

1. Hugo에는 문제, 선택 근거, 절차, 검증을 담은 기술 문서를 남깁니다.
2. Velog에는 같은 주제를 독립적으로 읽을 수 있는 이야기로 다시 씁니다.
3. GitHub에는 공개 가능한 설정 예제, 스크립트, 재현 절차를 둡니다.

## 2. 설계 기준

기술 문서는 결론만 보여주지 않습니다. 환경과 전제, 시도한 방법, 실제 확인 명령과 결과, 남은 한계를 함께 기록합니다. 값이 없는 성과나 측정하지 않은 수치는 쓰지 않습니다.

두 발행 채널은 같은 문장을 복제하지 않습니다. Hugo 글은 기술적 근거를 중심으로 하고, Velog 글은 사건과 비유를 이용해 같은 개념을 쉽게 설명합니다. 두 글은 서로 연결하되 각각만 읽어도 이해할 수 있게 작성합니다.

GitHub 자료에는 비밀번호, 토큰, 사설 주소, 개인 식별 정보를 넣지 않습니다. 예시 값은 실제 값과 구분되는 형태로 바꾸고, 실행 전에 독자가 수정해야 할 항목을 명시합니다.

## 3. 산출물 구조

프로젝트 글에는 문제, 제약, 선택 근거, 구현, 검증, 한계를 둡니다. 노트에는 목적, 전제 조건, 절차, 확인, 복구 방법을 둡니다. Velog 초안은 `stories/`에서 따로 관리해 기술 문서의 정확성을 유지하면서 말투를 자유롭게 바꿀 수 있게 합니다.

예를 들어 백업을 다룬다면 “백업을 설정했다”에서 멈추지 않습니다. 어떤 데이터를 대상으로 했는지, 복구 시험은 어떤 조건에서 진행했는지, 성공을 무엇으로 판단했는지, 측정하지 못한 항목은 무엇인지 적습니다. 실제 환경과 결과는 검증 후에만 채웁니다.

## 4. 인터랙티브 입구와 정적 기록

사이트는 별도 JavaScript 패키지 없이 Hugo 템플릿, CSS, JavaScript로 구성했습니다. 프로젝트·노트·소개·검색·개별 글은 각각 고유한 정적 URL을 가지며, 본문 목차, 코드 복사, 태그, 정적 검색과 인쇄 스타일을 제공합니다.

홈은 이 기록으로 들어가는 인터랙티브 입구입니다. 첫 화면에는 입자로 만든 `Alcedo`만 보이고, 스크롤을 시작하면 같은 입자 풀이 다음 여섯 장면을 연속해서 오갑니다.

1. `Alcedo` 글자
2. 홈랩의 연결과 경계를 나타내는 네트워크 트리
3. 프로젝트 카드와 코드 패널의 외곽선
4. 다시 꺼내 읽을 수 있는 노트 두 장
5. 하나의 실험이 Hugo 기술 문서, Velog 이야기, GitHub 구현 자료로 갈라지는 발행 흐름
6. 전체 기록으로 이어지는 검색 입력창과 버튼

장면마다 새 파티클 효과를 시작하지 않습니다. 하나의 고정된 전체 화면 canvas와 particle buffer를 유지하고, 스크롤 진행값에 따라 각 입자의 목표 좌표를 다음 형태로 보간합니다. 설명과 링크, 검색 입력은 별도의 HTML 요소로 두어 canvas가 정보 구조를 대신하지 않게 했습니다.

이 효과는 정적 기록 위에 단계적으로 더해집니다. WebGL을 사용할 수 없으면 Canvas 2D renderer를 시도하고, renderer나 초기화가 실패하면 여섯 장면을 일반 문서 흐름으로 표시합니다. 동작 줄이기 설정에서는 연속 애니메이션 대신 현재 장면의 정적 형태를 사용합니다.

## 5. 검증 상태와 남은 과제

Hugo 0.166.0 프로덕션 빌드와 경고 검사, 프로젝트 Pages 하위 경로 기준의 내부 링크·자산·목차 앵커·canonical·sitemap 검사를 자동화했습니다. Velog 변환 도구는 코드 예시를 보존하면서 실제 본문의 상대 자산 링크만 공개 URL로 바꾸는 회귀 검사를 포함합니다.

2026년 9월 24일 Chromium에서 새 파티클 홈을 검증했습니다. 데스크톱 여섯 장면은 19,000개, 모바일은 10,000개의 같은 입자 풀을 유지했습니다. 첫 화면에는 `Alcedo`만 표시되고, 1440px·390px·320px와 844×390 가로 화면에서 배치와 링크를 확인했습니다.

장면 선택, Page Up/Down, URL hash 직접 접속, 뒤로·앞으로 이동, 크기 변경, 먹·종이 테마, 검색 모달과 마지막 검색 입력의 실제 결과를 확인했습니다. 동작 줄이기 설정에서는 반복 애니메이션이 멈추며, WebGL 강제 미지원 시 Canvas 2D의 1,800개 입자로 대체됩니다. 그래픽 컨텍스트 손실·복원과 모든 그래픽 기능 및 JavaScript를 끈 환경에서도 본문을 읽을 수 있는지 검사했습니다.

이 검증은 화면 크기와 기능을 에뮬레이션한 Chromium 기준입니다. 실제 모든 휴대폰이나 Safari·Firefox 버전의 동작을 보장하는 것은 아닙니다. 이후 실제 학습 기록을 반복해 작성하며 템플릿에서 빠진 근거 항목을 보완하고, 공개 전 민감 정보와 링크를 다시 검사합니다.
