## 1. 문제

홈랩과 보안 공부는 설치가 끝난 순간보다 판단과 검증 과정에 더 많은 정보가 남습니다. 하지만 메모가 명령어 조각, 작업 후기, 저장소로 흩어지면 다시 찾기 어렵고 다른 사람도 작업의 맥락을 이해하기 어렵습니다.

이 프로젝트는 한 번의 학습에서 세 가지 결과물을 만드는 구조를 정의합니다.

1. Hugo에는 문제, 선택 근거, 절차, 검증을 담은 기술 문서를 남깁니다.
2. Velog에는 같은 주제를 독립적으로 읽을 수 있는 이야기로 다시 씁니다.
3. GitHub에는 공개 가능한 설정 예제, 스크립트, 재현 절차를 둡니다.

## 2. 설계 기준

기술 문서는 결론만 보여주지 않습니다. 환경과 전제, 시도한 방법, 실제 확인 명령과 결과, 남은 한계를 함께 기록합니다. 값이 없는 성과나 측정하지 않은 수치는 쓰지 않습니다.

두 발행 채널은 같은 문장을 복제하지 않습니다. Hugo 글은 기술적 근거를 중심으로 하고, Velog 글은 사건과 비유를 이용해 같은 개념을 쉽게 설명합니다. 두 글은 서로 연결하되 각각만 읽어도 이해할 수 있게 작성합니다.

GitHub 자료에는 비밀번호, 토큰, 사설 주소, 개인 식별 정보를 넣지 않습니다. 예시 값은 실제 값과 구분되는 형태로 바꾸고, 실행 전에 독자가 수정해야 할 항목을 명시합니다.

## 3. 산출물 구조

프로젝트 글에는 문제, 제약, 선택 근거, 구현, 검증, 한계를 둡니다. 노트에는 목적, 전제 조건, 절차, 확인, 복구 방법을 둡니다. Velog 초안은 `stories/`에서 따로 관리해 기술 문서의 정확성을 유지하면서 말투를 자유롭게 바꿀 수 있게 합니다.

예를 들어 백업을 다룬다면 “백업을 설정했다”에서 멈추지 않습니다. 어떤 데이터를 대상으로 했는지, 복구 시험은 어떤 조건에서 진행했는지, 성공을 무엇으로 판단했는지, 측정하지 못한 항목은 무엇인지 적습니다. 실제 환경과 결과는 검증 후에만 채웁니다.

## 4. 구현과 검증

별도 JavaScript 패키지 없이 Hugo 템플릿, CSS, JavaScript로 구성했습니다. 입자 제목과 먹·종이 테마는 제공된 화면 레퍼런스를 블로그에 맞게 옮겼습니다. 글 읽기 화면에는 본문 목차, 코드 복사, 태그와 정적 검색을 추가했습니다.

화면 효과는 읽기 기능 위에 더하는 방식으로 구현했습니다. WebGL을 사용할 수 없으면 Canvas 2D를 사용하고, JavaScript가 꺼져 있어도 제목과 글 목록은 HTML로 표시됩니다. 동작 줄이기 설정에서는 반복 애니메이션을 멈춥니다.

검증 시점은 2026년 9월 24일입니다.

- **빌드:** Hugo 0.166.0 프로덕션 빌드와 경고 검사를 통과했습니다.
- **경로:** 프로젝트 Pages의 하위 경로를 기준으로 내부 링크, 자산, 목차 앵커, canonical과 sitemap을 검사했습니다.
- **화면:** Chromium에서 데스크톱 1440px, 모바일 390px과 320px의 홈·글 읽기 화면을 확인했습니다.
- **기능:** 검색 결과와 빈 결과, 키보드 탐색, 테마 저장, 코드·글 링크 복사를 확인했습니다.
- **그래픽 예외:** WebGL 미지원 시 Canvas 2D 전환, 그래픽 컨텍스트 손실 시 일반 제목 표시와 복구, 동작 줄이기 설정을 확인했습니다.

실물 모바일 기기와 모든 브라우저 조합을 검사한 것은 아닙니다. 화면 연출과 폰트 렌더링은 기기마다 차이가 날 수 있습니다.

## 5. 남은 과제

실제 학습 기록을 이 구조로 반복해 보며 템플릿에서 빠진 근거 항목을 찾고 보완해야 합니다. 공개 글을 작성할 때마다 민감 정보 제거와 링크 유효성도 함께 확인합니다.
