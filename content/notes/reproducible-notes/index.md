## 1. 결과보다 조건을 먼저 적기

`성공했다`는 문장만으로는 같은 결과를 다시 만들 수 없습니다. 실행 전에 다음 정보를 남깁니다.

- 목적: 무엇을 확인하거나 바꾸려는가
- 범위: 어떤 장비, 서비스, 파일이 대상인가
- 전제: 필요한 버전, 권한, 네트워크 조건은 무엇인가
- 제외: 이번 작업에서 다루지 않는 것은 무엇인가

실제 주소와 계정은 공개 글에 적지 않습니다. `service.example.internal`, `<USER>`, `<TOKEN>`처럼 예시임을 알아볼 수 있는 값으로 바꿉니다.

## 2. 명령과 판단을 붙여 쓰기

명령어만 복사하면 왜 실행했는지 사라집니다. 각 단계에 목적과 기대 결과를 한 줄씩 붙입니다.

```text
목적: 서비스가 포트를 실제로 열고 있는지 확인한다.
명령: ss -lntp
기대: 대상 프로세스와 포트가 LISTEN 상태로 표시된다.
판정: 프로세스 이름, 포트, 바인딩 주소를 기록한다.
```

출력 전체에 민감 정보가 있을 수 있다면 공개 가능한 줄만 인용하고 무엇을 제거했는지 밝힙니다.

## 3. 성공 기준을 실행 전에 정하기

화면이 열리는 것만으로 전체 경로가 정상이라고 판단하지 않습니다. 예를 들어 서비스 접근을 확인한다면 DNS 해석, 연결, 인증, 실제 기능 수행을 각각 확인할 수 있습니다.

```text
[ ] 이름이 예상 주소로 해석된다.
[ ] 예상 포트에 연결된다.
[ ] 인증이 정상적으로 끝난다.
[ ] 핵심 기능을 한 번 실행하고 결과를 확인한다.
```

모든 항목이 필요한 것은 아닙니다. 이번 작업의 성공을 증명하는 최소 항목을 고르고, 확인하지 않은 항목은 `미검증`으로 남깁니다.

## 4. 되돌리는 방법까지 기록하기

변경 전 파일의 위치, 이전 설정으로 돌아가는 절차, 복구 후 확인 방법을 함께 적습니다. 되돌리기를 실제로 시험하지 않았다면 “복구 가능”이라고 단정하지 않습니다.

좋은 노트는 미래의 내가 그대로 따라 할 수 있고, 중간에 멈춰도 현재 상태를 판단할 수 있는 노트입니다.
