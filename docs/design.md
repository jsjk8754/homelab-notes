# 디자인 기준

## 1. 방향

Homelab Notes는 첫 화면에서 일반적인 포트폴리오 목록을 보여주지 않는다. 홈 전체를 하나의 긴 파티클 내러티브로 사용하고, 스크롤에 따라 같은 입자 집합이 여섯 장면 사이를 연속해서 변형한다. 별개의 캔버스 효과를 장면마다 교체하는 방식이 아니라 한 입자 풀의 위치·색·밀도·강조만 바뀌어 이야기가 이어져야 한다.

첫 진입 장면에는 `Alcedo`만 표시한다. 헤더, 장면 내비게이션, 소개 문장과 카드가 첫 인상을 방해하지 않게 숨겨지고, 사용자가 다음 장면으로 이동한 뒤에 정보 구조가 나타난다.

홈 밖의 프로젝트, 노트, 소개, 검색, 개별 글은 정적인 기술 저널이다. 홈의 움직임과 별개로 URL을 직접 열어 읽고 인쇄하고 공유할 수 있어야 한다.

## 2. 여섯 장면

모든 장면은 고정된 전체 화면 canvas와 같은 입자 풀을 사용한다.

1. **Title** — Instrument Serif italic으로 샘플링한 `Alcedo` 글자 형태. 첫 진입에서는 이 장면만 보인다.
2. **Network tree** — 홈랩의 연결과 경계를 나타내는 네트워크 트리. 입자는 루트에서 여러 노드로 흐르고, DOM 텍스트는 홈랩·네트워크·보안이라는 학습 범위를 설명한다.
3. **Project and code outlines** — 입자가 실제 프로젝트 카드와 `hugo.toml` 코드 패널의 외곽선을 따라 배치된다. DOM 콘텐츠는 계속 링크와 텍스트의 의미를 담당한다.
4. **Note sheets** — 입자가 두 장의 노트 윤곽으로 변형된다. 기술 노트를 다시 실행할 수 있는 지식으로 쌓는다는 의미를 전달한다.
5. **Publishing flow** — 하나의 실험이 Hugo 기술 문서, Velog 이야기, GitHub 구현 자료로 갈라졌다가 기록으로 모이는 흐름이다.
6. **Search pill** — 입자가 검색 입력창과 실행 버튼의 캡슐형 외곽선을 만든다. 이 장면에서 사용자는 정적인 검색 페이지로 이동할 수 있다.

장면 전환은 단순 fade 교체가 아니다. 현재 목표 좌표에서 다음 목표 좌표로 입자들이 실제 이동하며, 짧은 겹침 구간에서 두 형태를 보간한다. 포인터는 입자를 밀어내고 빈 공간은 spring motion으로 다시 채운다.

## 3. 화면 구조와 진행

홈의 canvas는 viewport 전체에 고정한다. 문서는 긴 scroll track을 제공하고, 현재 스크롤 비율을 0–5.82의 장면 진행값으로 바꾼다. 여섯 DOM section은 의미 구조, 링크, 검색 입력과 접근성 이름을 제공하고, 향상된 모드에서는 현재 장면만 화면 위에 고정한다.

오른쪽 장면 내비게이션과 URL hash는 같은 여섯 장면을 가리킨다. 키보드의 방향키, Page Up/Down, Home, End도 장면 단위 이동에 사용할 수 있게 한다. 사용자가 링크나 입력 요소를 조작하는 중에는 장면 키보드 명령이 가로채지 않는다.

`prefers-reduced-motion`에서는 연속 애니메이션을 멈추고 각 장면의 목표 형태를 정적으로 그린다. WebGL을 사용할 수 없으면 Canvas 2D renderer를 시도하고, renderer와 초기화가 모두 실패하면 canvas 향상을 해제해 여섯 section을 일반 문서 흐름으로 되돌린다.

## 4. Ink와 Paper

기본 `ink` 테마는 참고 화면의 짙은 먹색과 따뜻한 미색을 따른다.

- 배경 `#141413`
- 본문 `#e8e6dc`
- 보조 글자 `#a3a199`
- 강조 `#bd6b54`
- 구분선 `#33332e`

`paper` 테마는 같은 위계를 밝은 종이색으로 전환한다.

- 배경 `#eeeadf`
- 본문 `#242420`
- 보조 글자 `#646158`
- 강조 `#995139`
- 구분선 `#c9c3b6`

테마는 루트의 `data-theme` 값으로 전환한다. DOM 색, 브라우저 `color-scheme`, theme color와 파티클 팔레트가 함께 바뀌고 선택은 로컬 저장소에 보관한다.

## 5. 타이포그래피

`Alcedo`와 영문 장식 제목에는 Instrument Serif regular·italic을 자체 호스팅한다. 한국어 장면 제목과 읽기 본문에는 Noto Serif KR의 WOFF2 유니코드 서브셋을 자체 호스팅한다. 일반 UI에는 시스템 산세리프, 장면 번호와 메타데이터에는 시스템 모노스페이스를 사용한다.

Instrument Serif와 Noto Serif KR은 각각 저장소에 포함된 SIL Open Font License 1.1 문서와 함께 배포한다. 폰트 라이선스와 참고 파티클 소스의 출처·라이선스 상태는 서로 독립적으로 기록한다.

## 6. 정적 읽기 화면

프로젝트와 노트 목록은 큰 제목, 번호, 얇은 구분선을 사용하는 편집형 아카이브다. 개별 글은 760px 안팎의 읽기 폭, 한국어 세리프 제목, sticky 목차, 스크롤 가능한 표와 코드 블록을 사용한다. 소개는 2열 편집 구조, 검색과 404는 같은 타이포그래피 체계를 따른다.

작은 화면에서는 홈의 장면 텍스트와 시각 프레임을 재배치하고, 정적 페이지는 한 열로 바꾼다. 320px에서도 긴 코드·URL·표 때문에 문서 전체가 가로로 넘치지 않아야 한다.

## 7. 입자가 실제 글자를 만드는 전환

홈에서 글을 열면 같은 canvas의 입자가 실제 제목·설명·본문의 글자 획으로 모인다. 입자로 이루어진 문장을 먼저 보여준 다음, 동일한 위치의 선택·복사 가능한 HTML 본문으로 부드럽게 이어진다. 화면을 쓸고 지나가는 모래 마스크나 사각형 확대는 사용하지 않는다.

`article-glyphs.js`는 렌더링된 본문의 텍스트를 grapheme 단위로 측정한다. 실제 줄바꿈 위치, 글꼴, 굵기, 크기, 자간, 색상을 이용해 현재 화면에 보이는 글자만 작은 임시 Canvas 2D에 그린다. 글자 픽셀을 한 번 탐색하여 최대 16,000개 좌표를 뽑고, 모바일과 Canvas 대체에서는 입자 풀에 맞게 수를 줄인다. 사진 캡처나 외부 라이브러리는 사용하지 않는다. 폰트 로드를 제한된 시간 동안 기다린 후 좌표를 측정하고, 리사이즈·테마 변경 시 필요한 좌표만 다시 계산한다.

입자 엔진은 공간상 가까운 영역끼리 대응시켜 완만한 흐름을 따라 이동시킨다. 인접한 입자들이 공간상 연속된 경로와 출발 시차를 공유하며, 시작과 도착에서 속도와 가속도가 모두 0으로 잦아드는 5차 곡선을 사용한다. 펼치기는 약 2.4초이며, 진행도 75%까지 입자가 글자 형태를 완성하고 잠시 유지한 뒤 79.5–100% 구간에서 실제 본문으로 이어진다. 돌아가기는 약 1.7초 동안 같은 경로를 반대로 진행한다. 읽기가 시작되면 입자 렌더링을 멈춘다.

노트의 이전/다음 전환은 약 2.35초다. 기존 글자가 입자로 바뀌고, 그 입자들이 다음 글의 정확한 획 위치에 모여 새로운 문장을 만든다. 큰 흐름과 작은 보조 흐름을 함께 사용하되 글자에 가까워질수록 굽힘이 사라져 도착 후 흔들리지 않는다. 도착 글의 입자 형태를 먼저 완성한 다음 79.5–100% 구간에서 HTML로 전환한다. `reader-motion.js`에서 이동·출발 시차·본문 인계 시점을 공유하여 글자 완성과 본문 노출이 어긋나지 않게 한다. 전환 중 임시 본문과 최종 본문의 너비·툴바 경계를 일치시켜 마지막 순간에 줄바꿈이나 위치가 달라지지 않게 한다.

읽기 내용은 Hugo가 생성한 실제 HTML이며 주소·제목·canonical도 글에 맞게 바뀐다. 목차, 표 스크롤, 코드·주소 복사와 검색을 유지한다. Back/Forward는 글과 읽던 위치를 복원하고, 기록으로 돌아가기는 최초의 홈 장면과 링크로 복귀한다. 직접 접속한 노트에서도 같은 글 전환을 제공한다.

읽는 동안 홈은 inert 처리하고 장면 제어를 중지한다. 움직임 줄이기, JavaScript 비활성화와 그래픽 향상 실패에서는 실제 링크와 HTML로 읽을 수 있다. 글자 샘플링에 실패하면 빈 화면을 기다리게 하지 않고 HTML끼리 겹쳐 사라지고 나타나는 전환으로 대체한다. 폰트 대기 중 취소나 연속 history 이동은 현재 전환을 정리하며, 그래픽이 끊기면 즉시 읽기 상태로 마무리한다.

## 8. 검증 상태 기록

2026-09-24 Chromium에서 여섯 장면의 단일 풀 유지, 1440×1000·390×844·320×568·844×390 배치, 장면 선택과 history/hash, 검색·테마, reduced motion, Canvas 2D 대체, WebGL context 손실·복원, 전체 그래픽 실패와 JavaScript 비활성화 경로를 확인했다. 검사 도중 발견한 클릭 이벤트 중복 바인딩, 깊은 링크의 fallback 위치, 작은 화면의 프레임 잘림을 수정했다. 실제 모든 기기·브라우저 검증으로 확대 해석하지 않는다. 공개 배포는 main push 후 GitHub Actions 결과로 별도 확인한다.

2026-09-26 ego-browser의 Chromium에서 글 진입·복귀 전환을 확인했다. 1440×1000·390×844·320×568, 두 노트와 프로젝트, 목차·검색·주소 복사, history 뒤로/앞으로 및 연속 이동, 글 직접 접속·새로고침, 리사이즈, Ink·Paper, 로딩 취소·실패, 로딩 중 reduced motion 전환, Canvas 대체, WebGL context 손실·복원, JavaScript 없는 링크 이동을 검증했다. 조기 클릭 시 흩어진 입자가 확대되는 현상, 복귀 후 RAF 미재개, 연속 뒤로 가기의 장면 불일치와 전환 중 본문 노출 범위를 수정했다. Safari·Firefox와 실제 휴대전화는 별도 검증이 필요하다.

같은 환경에서 흐르는 펼치기와 양방향 책장 전환을 추가 검증했다. 홈·직접 접속 모두의 이전/다음, 글별 스크롤 복원, 전환 도중 연속 Back/Forward, 접는 중 다른 글 재진입, 새로고침 뒤 Back/Forward, 320px·390px 레이아웃, 복사·검색·Canvas 대체·context 복구를 확인했다. 늦은 fetch와 close 애니메이션의 경합, 잘못된 history entry에 스크롤 위치를 저장하는 문제를 수정했다.

이후 종이 확대와 책장 접기를 제거하고 샌드 페인팅 전환으로 교체했다. Chromium의 1440×1000·390×844·320×568에서 중간 프레임, 홈과 직접 접속의 노트 이동, 프로젝트 펼치기, Ink·Paper를 확인했다. 12회 연속 전환 후에도 canvas·입자 풀이 같고 SVG 하나와 마스크 두 개만 유지되며 읽기 상태에는 마스크가 해제됨을 검증했다. 스크롤 1200px 복원, 전환 중 Back/Forward·복귀 취소·리사이즈, WebGL 손실·복구, 실행 중 및 초기 reduced motion, Canvas 2D·CSS mask 미지원·JavaScript 비활성화 경로도 통과했다. 전환 종료 후에는 입자 RAF가 멈추고, 홈 복귀 시 다시 실행된다. 테스트 브라우저의 실제 전환 표본은 47프레임, 평균 간격 32.3ms였으며 모든 기기에서 60fps를 보장한다는 의미는 아니다. JavaScript 문법 검사와 Hugo 전체 검사를 통과했다.


글자 좌표 기반 전환에서는 Chromium 1440×1000, 390×844(DPR 2), 320×568을 확인했다. 실제 본문 opacity가 0인 진행도 약 71%의 펼치기와 75%의 글 넘기기에서 입자만으로 제목·설명·본문이 형성됨을 확인했다. 모바일 제목의 입자 단계와 최종 HTML 사이 x·y·너비·높이 변화는 모두 0이었다. 6회 연속 이동 후 같은 canvas와 입자 풀, 읽기 화면 하나가 유지됐고, 1200px 스크롤 복원과 전환 중 Back/Forward를 확인했다. 글자 샘플링 실패를 주입했을 때 두 HTML 본문의 투명도가 상보적으로 변해 공백이 생기지 않았다. 전환 중 리사이즈와 WebGL 손실·복원도 통과했다. 좌표 추출은 CSS 픽셀 래스터와 단일 픽셀 탐색으로 줄였으며, 지연된 프레임이 글자 형성 단계를 건너뛰지 않도록 프레임당 진행 시간을 최대 48ms로 제한한다.

최종 곡선 계산 최적화 후 전환 표본은 114프레임이었다. 시작 시 약 1초의 RAF 지연이 관측됐지만 첫 진행량은 2.67%로 제한되어 글자 형성을 건너뛰지 않았다. 전체 표본의 평균 간격은 24.2ms였으며 이는 해당 Chromium 실행 환경의 관측값이다. 폰트 대기 중 Escape, 초기 reduced motion의 실제 HTML 표시, 1,800개 입자의 Canvas 대체 전환을 재검증했고 JavaScript 오류는 없었다. Hugo 전체 검사와 세 JavaScript 모듈의 문법 검사도 통과했다.

추가 배포 검증에서 RAF가 초당 약 한 번으로 지속 제한되는 환경을 발견했다. 이 경우 프레임 제한만 적용하면 읽기까지 수십 초가 걸리므로, 전환 시간에 2초를 더한 시점 이후 첫 RAF에서 즉시 본문을 표시하도록 보완했다. 제한된 환경에서도 펼치기와 글 넘김이 최종 opacity 1로 끝나고, 전환 상태·입자 RAF가 정리되며 오류가 없음을 확인했다. 중단된 전환을 뒤늦게 완료할 별도 타이머는 추가하지 않았다.

물 흐르듯 이어지는 경로로 조정한 뒤 1440×1000에서 펼치기의 30%·50%·78%와 글 넘김의 45% 프레임을 확인했다. 390×844(DPR 2)의 78% 단계에서 두 HTML 본문의 opacity는 모두 0이고, 입자만으로 글자가 형성됐다. 최종 본문 인계 시 제목의 x·y·너비·높이 차이는 모두 0이었으며 320×568에서도 가로 넘침이 없었다. 800px 스크롤 복원, 전환 중 Forward→Back, 같은 canvas·입자 풀 유지, 런타임 reduced motion, 홈 복귀, Canvas 2D 대체와 glyph 샘플링 실패의 HTML 전환을 확인했고 오류는 없었다. 수학 검증에서는 단조로운 진행, 유한 좌표, 시작·도착의 속도·가속도 0, 정·역재생 좌표 일치, 글자 완성 후 105ms 이상의 유지 구간을 확인했다. 프레임별 임의 시간차와 삼각함수 계산을 제거하고 경로 계수를 한 번 계산해 재사용한다. JavaScript 문법 검사, Hugo 빌드, 4개 테스트와 18개 HTML 검사도 통과했다.
